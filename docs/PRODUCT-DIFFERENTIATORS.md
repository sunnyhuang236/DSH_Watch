# 产品差异化要点（先记录，后续再展开）

> 来源：2026-11-15 与用户确认。用于 M3/M4、对外介绍与后续产品取舍；不混入 P0 运维硬化。

1. **“是否需要你介入”的状态语义**
   - 7 种 `turn/end` reason 映射（completed / aborted / error / max-tokens / blocked / interrupted / forked）；
   - 等待撤销：等待解除后作废未投递提醒；
   - 终态按 run 不可逆，新 run 才允许重新 running；
   - 工具报错 ≠ 任务失败（`tool/result.isError` 不改变终态）。

2. **通知决策质量**
   - 去重键：`event_id + installation_id + kind`；
   - 等待解除撤销 + 3 秒合并窗口取最终态；
   - 隐私 payload：只含不透明任务引用与通用 kind，不含标题/摘要/路径；
   - 提醒记录本机兜底（系统通知关闭也能回看）。

3. **可验证的工程证据**
   - 63 项自动化测试（M1 42 + M2 21）；
   - V06 真机 20/20 到达（100%，iPhone 17 Pro Max / iOS 27.0.1）；
   - 真实 DSH 0.2.2-rc.1 内加载 + 重启自动加载；
   - 13 份脱敏回归样本（真实 + 合成 + 外部实测依据）。

4. **M4 的审批/提问 hook**
   - `ctx.on('approval/request', (req, next) => …)` 与 `ctx.on('user-questions/request', …)` 可包装；
   - 多数社区项目只做远程 UI，不深入做审批/提问的语义与回执；
   - M4 手机审批需处理“Host 在线 + 请求只在内存/重启丢失 + 请求不含工具参数”。

## 使用原则

- 对外定位：**“任务是否需要你介入”的盯梢器**，不是第二套远程 IDE/屏幕镜像。
- 竞争上不与 dsh-pocket（2,961★）/ ds-harness-remote（2,881★）比全量远程；用状态语义 + 通知质量 + 可验证工程数据做差异。
- 后续 M3/M4 若做新功能，优先服务上述 4 条，不扩成完整客户端。
